# 数据库与接口

数据库结构见data/install.sql：20张业务表，MySQL 8，InnoDB/utf8mb4，表名wc_模块_实体；每张表和字段提供COMMENT。已在独立数据库建立，赛事业务数据待导入。

公共及社区9表：wc_sys_user、wc_sys_team、wc_sys_member、wc_content_announcement、wc_sys_assignment、wc_sys_audit、wc_sys_notification、wc_fan_post、wc_fan_comment。
赛事及收藏11表：wc_data_tournament、wc_data_stage、wc_data_group、wc_data_stadium、wc_data_team、wc_data_player、wc_data_squad、wc_data_match、wc_data_event、wc_fan_team_favorite、wc_fan_match_favorite。

统一主键id，外键实体名_id；user的created_at/updated_at用整数兼容Yii TimestampBehavior，其余DATETIME并统一时区。业务状态采用明确字符串，发布内容默认draft/pending，删除采用archived等状态。禁止把体育国家队和开发团队共用同一表。
比赛有normal_home/away、extra_home/away、penalty_home/away独立字段。赛果展示和统计排除点球大战射门；加时是否计入某项指标由接口明示。小组积分和排序规则在设计文档固定并与官方榜单核对。比赛事件标记进球/点球/乌龙球/红黄牌，射手统计按事件类型处理，不能直接把比分之和当个人进球。
收藏表按用户+目标唯一；阵容按届次+国家队+球员唯一；比赛按届次+比赛编号唯一；事件按来源事件编号去重。导入器先校验引用关系、日期、比分与阶段，再事务写入。

接口约定：site/me返回登录状态、用户ID与角色；赛事接口按tournament_id/stage_id/team_id/date分页；统计返回维度、数值、单位及统计口径；社区关联match_id可空；后台必须服务器端校验角色。所有写操作校验CSRF和所有权，返回错误应明确。
